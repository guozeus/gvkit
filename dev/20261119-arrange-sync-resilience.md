# 自御配置同步损坏定向修复（2026-11-19）

## 目标与边界

同一坏配置只提示一次；配置损坏不阻断事项原件的只读列表；本机降级不回写共享配置；正常变更从最新有效内容更新涉及字段，避免过期整份状态覆盖。

本轮只制作、隔离验证和提交源码，不发布、不修改正式 Vault、同步设置或自动迁移。主线起点 c6736c414a5600387270bc306715ab73b0659215 / 0.6.75。原未跟踪资料保持，版本号和安装产物不变。

## 已证机制

- 打开视图的 enableRewards、view_open、布局就绪可独立加载并弹三次错误。修复移除单独奖励加载与额外布局就绪加载，合并在途视图刷新；文件变更到来时保留一次后继刷新。界面刷新与业务操作共用现有队列。
- 官方 headless 0.0.14 原样纯文本合并函数在合法合成三方 YAML 上可产生 UUID 断片及非法 YAML。纯函数提取 SHA-256 27efb93f7d767db6d5783526608fec1646b136e91acce8647453d5b44a343bba；固定种子291119、24个合成UUID的案例1188可产生无缩进尾巴。真实事故首台设备、两端合并前原文未证，不能将此实验冒称事故完整复现。

## 实际改动

- Store 区分配置异常与其他异常。配置解析/校验失败仍从事项原件装载列表；按本机单份最后有效设置或默认顺序显示，显式标明每日目标和奖励暂不可确认。不从缓存猜目标、不启用或发放奖励、不把降级状态写回；语法损坏和形似UUID却截断的身份均不能成为健康缓存。
- 最后有效设置及已提示的配置指纹仅保存本机 localStorage，不写共享文件、不进入诊断导出。不能存储时继续显示列表，使用内存状态。
- 坏配置下业务写入拒绝；暂缺配置的打开/刷新不初始化。保留首次安装的明确用户配置/创建以及显式 enableRewards API 初始化路径，已有坏文件不走此路径。
- 同一配置异常在共享 Store 中聚合提示，视图重开不反复弹窗；有效配置重新加载后结束该异常状态。其他操作、事项文件和IO错误仍按原路径报告。
- saveState 比较本次变更与加载基线，从 Vault.process 当前有效配置只修改本次改变的顶层字段，保留无关及未知字段；同字段已变且不等于本次意图时拒绝覆盖。无实际变化跳过写入。显式完成/撤销、归档和钉住操作仍保存其必要排序归整，避免破坏原钉住槽位语义。
- 复用现有 Trace，只保留异常/冲突，不保存逐次成功流水。包括触发、run、阶段、版本/平台、源和候选指纹；同坏版本聚合首次/最后时间、次数及最近run/trigger。异常仍脱敏，不含事项正文、完整YAML、原错误片段或凭据。
